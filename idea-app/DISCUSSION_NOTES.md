## 一、项目定位

- **名称**：点子
- **核心承诺**：激发用户产生新思路和新点子
- **形态**：内容平台（非纯工具）
- **内容构成**：UGC 60% + PGC 40%（冷启动期 PGC 反超到 70%+）
- **社交**：公开全开放，面向"开源精神"创意社群
- **所有权**：默认全公开，先做极端版，后续按用户反馈加私密选项
- **商业**：订阅制（暂定，先开发不上线，社群测试后再定）
- **目标用户**：创意工作者/创业者/设计师/写作者/教育者/热心生活创意的人
- **社群愿景**："创意、分享和实现"的聚落

## 二、调研结论（详见可行性分析）

### 现有产品两派分立，中间留白
- **派别A**："AI直接给答案"（Idea Generator系）——用户被动接收，创造力未被激发
- **派别B**："协作白板/固定卡牌"（Ideamap、Oblique Strategies）——要么太重，要么无个性化
- **空白**：轻量、个人化、基于创造力科学研究的"激发式"App

### 5个可产品化的科学机制
1. **随机刺激** → 打破思维惯性（ScienceDirect 2021）
2. **心智游走 + 中等engagement活动** → "淋浴效应"（APA PsycNet 2023）
3. **跨域类比** → 突破性创新（EconStor）
4. **发散思维 + 收敛思维 双阶段**（OECD PISA）
5. **约束反而激发创意**（经典研究）

### 经典创意技法（可做prompt模板）
SCAMPER / TRIZ 40原理 / Oblique Strategies / Six Thinking Hats / How Might We

## 三、视觉形式

### 主页
- **圆圈大小不一，无规则随机分布**
- **隐喻**：想法像气泡——浮起、碰撞、合并、破裂
- **呼应"随机刺激"科学机制**（非装饰，是产品化）

### 圆圈视觉编码（三层）

| 维度 | 编码方式 | 说明 |
|---|---|---|
| 热度 | **大小** | fork数+近期衰减；唯一热度指标 |
| 随机刺激 | **颜色** | 12-16色池真随机分配，与内容完全解耦 |
| 自己/别人 | **边框** | 金色细边框=自己产生；无边框=收藏的 |

### 颜色规则（重要）
- **12-16色池**，明度饱和度都有变化（太少会成"伪分类"，太多会视觉混乱）
- **真随机分配**，禁止按内容哈希（否则又成隐藏分类）
- 用户应能发现"红色圆圈点开有时是科技有时是散文"——这种错位感正是打破预测惯性
- **暗色模式**专门设计一套色系
- 色盲用户不受影响（颜色不承载语义）

### 圆圈内容预览：方案C（完全空白）
- 圆圈上**不显示任何文字**
- 用户必须"点开看"才能知道内容
- 强制随机激发，禁止用户主动筛选

### 圆圈微动效（产品语言，非装饰）
- 轻微浮动（气泡感）
- 悬停时轻微放大+柔光
- 被fork瞬间涟漪扩散（视觉化"激发"发生了）
- 长时间未fork的圆圈慢慢变灰变薄（种子淡出视觉化）
- **PRD必须写入交互细节，不能后期被当"锦上添花"砍掉**

### 工程/体验坑
- 触控目标最小 60pt，重叠自动避让
- 无限滚动：伪随机+滚动延展算法

## 四、核心交互流程

### 双引擎模型

#### 引擎A：被动激发
```
浏览圆圈 → 点击展开看别人的点子 → "这条让你想到什么？" 联想引导
→ 用户写下的联想 = 自己的点子（金边圆圈）→ 入仓库
```

#### 引擎B：主动激发
```
"今日激发点"入口 → 每日一题（随机词/类比/约束/反向提问）
→ 3分钟倒计时思考 → 写下想法 → 入仓库为金边圆圈
```

### 仓库点子双类制（用边框区分，非颜色）
- **金色细边框**：自己产生的点子（联想/今日激发点/直接发布/fork演化产物）
- **无边框**：收藏的别人的点子（引子）
- **颜色仍为随机分配**，边框逻辑与颜色解耦
- 用户的点子才是App核心资产

## 五、演化机制（仓库内）

### 演化操作（2项，已砍掉连线和种子）
- **碰撞**：选两个点子 → AI生成3个结合方案 → 用户选一个 → 新点子入仓库（金边，parent_ids=[A, B]）
- **演化**：选一个点子 → 选SAMPER角度 → AI生成3个变体 → 用户选一个 → 新点子入仓库（金边，parent_ids=[原点子]，evolved_from={angle}）

**SAMPER 6角度**（去掉C=Combine，已由碰撞功能承担）：
- **S**ubstitute（替代）：这个点子里什么可以被替换？
- **A**dapt（适应）：能从其他领域借鉴什么？
- **M**odify（修改）：放大或缩小某个方面？
- **P**ut to other use（其他用途）：这个点子还能用在哪里？
- **E**liminate（消除）：去掉什么会让它更好？
- **R**everse（反转）：反过来想会怎样？

**AI生成模式**：每次生成3个方案/变体，用户选一个采纳（可编辑后采纳）
- 碰撞3方向：实用型 / 跨界型 / 反常规型
- 演化3距离：近（微调）/ 中（明显变形）/ 远（大胆重构）

**每日次数限制**：
- MVP阶段：不限制
- 后期：建立成本模型，根据AI调用成本限制每日碰撞+演化次数
- **科学依据**："约束激发创意"——不仅是内容约束（300字），行为约束（次数限制）也激发创造力

~~连线~~：**已砍掉**（2026-07-07）
- 理由：App是"创意激发"非"知识管理"，连线是笔记软件核心feature，放进来自喧宾夺主
- 连线一旦做了，用户会期待双向链接/关系类型/图谱可视化/过滤搜索…功能树失控
- 与圆圈随机分布的"无序哲学"矛盾（连线=建立秩序）
- 碰撞已吸收连线的价值（表达"有关系"+让AI说清关系+产生新点子，比静态连线更动态）

~~种子~~：**已砍掉**（2026-07-07）
- 理由：种子（主动淡出）和自然淡出（被动淡出）功能重叠，简化为单一机制
- 演化菜单从4个减到2个，更聚焦

| 机制 | 交互 | 科学依据 |
|---|---|---|
| 碰撞 | 选两个点子 → AI生成3结合方案 → 用户选 | 跨域类比 |
| 演化 | 选一个点子 → 选SAMPER角度 → AI生成3变体 → 用户选 | 经典创意技法 |
| ~~连线~~ | ~~已砍~~ | ~~已砍~~ |
| ~~种子~~ | ~~已砍~~ | ~~已砍~~ |

### 自然淡出机制（被动，唯一生命周期管理）
- **一周未触碰** → 圆圈慢慢变小变淡
- **一周后移出仓库** → 从用户仓库消失
- **数据模型关键**：移出仓库 ≠ 删除点子
  - 如果点子被别人fork过 → 点子在系统中永久存在（谱系图的一部分），只是从当前用户仓库移出
  - 如果点子没被fork过 → 可以彻底删除
  - 这保证了fork关系链不会断裂

### 演化菜单交互
- 点击圆圈 → 弹出演化菜单（2个选项：碰撞/演化）
- 漫游式路径展开 + 震动反馈（原生App）
- 方案A（已确认）

## 六、核心创新：点子谱系图（GitHub for Ideas）⭐

### 设计动机
"开源精神"不能停留在口号，必须落地为机制。让点子像代码一样可 fork、可 merge、可追溯出处。

### Fork（衍生）
- 用户B基于A的点子写变体 → 自动标注 `forked from A`
- A收到通知"你的点子被fork了"——荣誉而非损失

### Merge（碰撞）
- 两个点子碰撞产生的新点子 → 记录两个父节点
- 谱系图上可见"X和Y的孩子"

### Lineage（谱系树）
- 每个点子详情页下方有一棵树：祖先 → 它 → 后代
- 一个好点子几年后长出一棵大树，原创者始终在树根
- 视觉化"开源精神"：贡献永久被记录

### 护城河
- 其他App的点子是孤立的，"点子"App的点子有血脉
- 用户有"在创意谱系中留下印记"的归属感——比积分/勋章更高级的留存驱动

### 风险与对策
- 可视化复杂：初期只做2层（父+子），后期再做完整树
- "我的原创"情结：加"拒绝衍生"开关，默认开放
- 垃圾fork：fork也走联想引导流程，不能空壳

## 八、关键设计决策（截至 2026-07-07）

### 内容与所有权
- UGC 60% + PGC 40%（冷启动期 PGC 反超到 70%+）
- 全公开默认，先做极端版
- 面向"开源精神"创意社群
- **共识：没有"烂点子"**——一个人的烂点子可能是另一个人的好点子
  - 不做"踩/差评"功能
  - 不做内容质量分级（PGC/UGC平等展示）
  - 不做"优质点子"筛选算法
  - "热门"只是"被fork多的客观描述"，不是"好"的评价
  - 边界：违规内容（广告/辱骂/抄袭）仍需审核机制
- **审核机制**：AI审核 + 互联网违禁词库 + 用户举报 + 人工二审
- **审核时机**：先发后审（不阻塞UGC），AI秒级审核，违规立即撤回
- 比先审后发对UGC友好得多

### 视觉
- 圆圈大小不一随机分布，无规则
- 圆圈**不显示任何文字**（方案C，强制随机激发）
- **颜色真随机**（12-16色池，与内容解耦）
- **边框区分**：金色细边=自己产生，无边=收藏的
- 圆圈微动效（浮动/悬停发光/fork涟漪/淡出）是产品语言

### 字数与分类
- 点子**≤300字**（约束激发，浓缩表达）
- **不加 type**（避免分类思维，强化发散定位）
- **不加 tag**（同上，避免分类焦虑）
- App性质从"信息消费"变为"创意激发"

### 搜索
- **坚决不做搜索**
- 但**谱系图导航必须做**（沿fork关系走，不是搜索）
- 边界要在PRD写清楚，防止后期被需求方塞回来"加搜索框"

### 热度算法
- **纯fork数**（+近期衰减，用于种子淡出）
- 拒绝复杂算法，与抖音式推荐划清界限
- 种子淡出机制平衡马太效应（老点子无人fork会变小淡出）
- **主页圆圈构成：90%随机 + 10%热门**（在比例上规避马太效应，但保留少量热门曝光）
- 10%热门 = **近30天fork数Top**（滚动窗口，每日重算，非固定月初）

### 个人主页
- **显示该用户仓库所有点子**（自己产生的+收集的）
- 隐喻：**进入一片森林，而非攀爬一棵树**
- 只看自己产生=沿fork回溯一条血脉线（窄）
- 看所有=看到这个人的"思想食物+思想产物"生态（宽）
- 与点子谱系图正交互补：谱系图=纵向家族树，个人主页=横向思维森林

### 演化菜单交互
- **点击触发**（非长按，发现性更好）
- **模拟步行体验**：菜单展开有"漫步"动效
- **轻微震动反馈**：模拟脚步触感
- **科学依据**：把"心智游走/淋浴效应"机制产品化到物理交互层——身体微动+心智游走=激发创造力
- 形态：**方案A 漫游式路径**（已确认）——菜单像圆圈旁边的路径展开，用户点击路径选项，震动反馈模拟脚步
- **技术选型：原生App**（已确认）
- **技术栈：Flutter**（已确认 2026-07-08）
  - 一套代码双端（iOS+Android）
  - CustomPainter画圆圈，动画框架支持浮动/涟漪/淡出
  - HapticFeedback class全平台支持震动反馈
  - 状态管理待定（Riverpod / Provider / Bloc）
- **开发工具**：Trea IDE / Codex / WorkBuddy（三个vibecoding工具均可）
- **后端**：FastAPI + PostgreSQL（fork关系用递归CTE查询，MVP够用）+ Redis + DeepSeek
- **输出物**：PRD（PDF）+ Trea IDE环境配置与最优方法（MD）

### 今日一点（原"今日激发点"）
- **改名**：激发点 → 一点（双关：一个点子 + 一点儿灵感；轻盈感强；呼应App名"点子"）
- 3分钟倒计时
- **倒计时结束自动保存草稿**，可继续写（呼应心智游走：灵感可能在别处冒出）
- **错过当日不能补做**（强化稀缺性）
- "当日"定义：0:00-23:59（先按单时区，多时区后期再说）
- **草稿随当日过期**：保存到当日23:59，第二天清空
- 第一次保存草稿时弹窗说明（之后不再弹，避免骚扰）
- 弹窗文案友好："📝 草稿已保存。保留到今晚23:59，明天就清空啦，记得回来完成！"

### UI用词规范
- "收藏" → "**收集**"（弱化占有感，更符合开源精神；像森林捡拾落叶而非锁进箱子）
- "激发点" → "**一点**"（双关趣味，呼应App名）
- 统一称呼：入口"今日一点"，历史"过去的一点"，产物仍是金边圆圈

## 九、点子数据结构

```
点子 Idea
├─ id（唯一）
├─ content（≤300字文本）
├─ source（ugc / pgc / today_spark / fork / merge）
├─ author_id
├─ color_hex（从12-16色池真随机分配，与内容解耦）
├─ border_style（none / gold-thin）— 个人主页区分自己/收藏
├─ parent_ids[]（fork关系，可有多个父，用于merge）
├─ children_ids[]（被fork的子点子）
├─ heat = fork_count（唯一热度指标）
├─ size = f(fork_count, 近期fork衰减)
├─ status（active / fading / faded）— 种子淡出
├─ last_fork_at（用于种子淡出计算）
├─ forkable（默认true，可设false拒绝衍生）
├─ created_at
└─ evolved_from[]（演化链：1.0→2.0→3.0）
```

**砍掉的字段**：
- ~~type~~（避免分类思维）
- ~~tags[]~~（避免分类焦虑）
